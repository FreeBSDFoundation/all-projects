# FreeBSD Foundation CRA Update \- October 2026

## Summary

During October, the FreeBSD Foundation continued to make progress on the project, with developments across vulnerability handling, Software Bill of Materials (SBOM), public documentation, and community engagement.

The SBOM toolchain workstream reached an important milestone with the acceptance of an initial community-provided solution for the Ports collection into the FreeBSD tree. Work continues to progress the equivalent solution for the base system, alongside improvements to supporting tools, metadata, and vulnerability reporting formats.

The Foundation also advanced its preparations for CRA-related vulnerability reporting, including providing reference material to the Security Team, and beginning the process of choosing the appropriate EU state for the Foundation to engage with on reporting obligations.

A broader project review has been completed, with recommendations for future priorities and scope now under internal consideration.

Public-facing CRA resources have become easier to find, and a project update blog post has been published.

## Workstream updates

### Security, and vulnerability handling

The Foundation has created a draft Vulnerability Action Pack for the FreeBSD Security Team to use in the event of a live security incident that triggers CRA reporting requirements, either for a FreeBSD vendor or for the Foundation itself. The pack is intended to provide key reference information relating to the CRA to support the Security Team’s processes.

The Foundation has also completed a review of this project (Cyber Resilience Act Readiness), assessing progress against its original goals and considering the appropriate scope of future work. The resulting recommendations are currently being considered internally.

Engagement with the FreeBSD Core Team has continued, with the Foundation providing information and support on understanding the CRA. In addition, the Foundation has begun a process to identify the most suitable EU member state for it to align with for future reporting obligations. Each state has a Computer Security Incident Response Team (CSIRT) and open source software stewards must determine a reference one to report to.

### SBOM toolchain

Significant progress has been made on the SBOM toolchain, particularly for the Ports collection. An initial solution proposed by a community member has been reviewed by Foundation developers and accepted into the FreeBSD tree. Downstream users are encouraged to try the solution and provide feedback to help guide further improvements.

The SBOM solution for the FreeBSD base system remains under review. The project team is actively seeking engagement from key base system committers to support its inclusion.

Supporting development work continues to improve the completeness and maturity of the base system SBOM solution. This includes adding missing SPDX tags, with several outstanding reviews that the team intends to raise with the Source Manager team to help accelerate progress. The update to the pkgconf tool to support SPDX has now been completed and incorporated into the base system.

Work to add CycloneDX support to the SBOM solution is nearing completion, with tests currently being written. Progress has also resumed on adding FreeBSD support to Package URL (PURL), following an extended period in review.

The project is also working towards the inclusion of pkg in the FreeBSD base system. This is an important dependency for SBOM generation and would also support the separate packaged base initiative (pkgbase), which sits outside the scope of the CRA readiness project.

Finally, the Ports Security Team has renewed its prioritisation of the migration from VuXML to the Open Source Vulnerabilities (OSV) format. This renewed support is expected to help move the work towards completion.

### Public documentation

The Foundation's public CRA reference pages are now more easily discoverable through a link in the website navigation menu. These resources provide information to help FreeBSD users and downstream manufacturers understand the legislation and its implications.

The documentation is available on the [FreeBSD Foundation CRA pages](https://freebsdfoundation.org/eu-cyber-resilience-act-cra/).

The Foundation has also welcomed the external questions it has received about aspects of its proposed vulnerability reporting arrangements. These were submitted through its dedicated contact address, [cra@freebsdfoundation.org](mailto:cra@freebsdfoundation.org). Responses to these questions will be incorporated into the public documentation in due course, helping to clarify the Foundation's approach. Further questions and feedback are welcome.

### Community legislative engagement

No new calls for community engagement relating to the Cyber Resilience Act were identified during October. The Foundation continues to monitor opportunities for relevant engagement.
